# D2b part 4 — fail-closed recovery hold before restore adoption

**Scope:** First client-side pre-adoption safety gate and private owner-initiated export UI. This does **not** activate 2b partition, server ACL, import/replay or automatic reconciliation.

## Behavior

- On a mismatch between the browser's known `restoreGeneration` and the server's, `adoptServerCopy` must first write an opaque `ai-executive-offline-recovery-hold` marker to `localStorage`, then return **without** clearing any Dexie tables, merge base, marker or draft. The marker stores only numbers (known/observed generation and creation time), not record IDs or content.
- Startup compares the generation immediately after the first server GET: before legacy migrations, default-workspace seeding and a previously interrupted sign-out wipe. A known mismatch blocks writes in its detecting tab immediately, and takes the shared lock before persisting the browser-wide stop. A marker retained on reload also suppresses the interrupted wipe. Pull-from-server must check restore generation **before** comparing snapshot revisions, including when a restore rolls the revision backward.
- Finalizing a recovery hold and a user-authorized destructive sign-out wipe use the **same** exclusive Web Lock. A hold cannot become globally visible halfway through multi-key deletion: an already authorized wipe finishes first, or a pre-existing hold blocks the wipe before it starts. The detecting tab immediately blocks its own writes while waiting for the lock. Browsers without Web Locks refuse destructive wipes. Previously persisted pending-intent keys remain valid recovery stops for compatibility. If an already-started authorized wipe wins, the restoring tab reloads to sign-in rather than presenting an invalid rescue for emptied data. An interrupted wipe likewise cannot be advertised as a valid rescue source; test these interleavings in two real browser tabs before merge.
- The marker persists across tab reloads and browser restarts. Its presence makes the Dexie middleware refuse writes in **all** tabs and makes the client refuse same-origin mutating APIs (other than the three narrowly defined sign-in routes). A storage/marker error fails closed; it does not permit destructive adoption.
- A non-dismissible modal explains the freeze. The owner deliberately chooses **Prepare recovery file**, then **Download file**. Preparation reads server state with GET, then takes two matching local DB/draft/marker snapshots. It uses the canonical D2b v1 recovery bundle and bounded UTF-8 codec from PR #111/#112. Invalid/over-limit input refuses the whole export: no truncation, no cleaned-up drafts, no adoption.
- Notes and project-context drafts are captured as **raw storage keys and values**, including entries the normal draft readers would otherwise ignore. Pending deleted/revived markers are read without legacy migration or deletion, respecting newest intent; corrupt/ambiguous legacy markers cause an error.
- Repeated server restores do not prevent rescue: a file is stamped with the current generation if it is at least the first one observed while frozen. A base revision unverified after reload is encoded explicitly as `null` (unknown), rather than made-up revision zero; existing numeric v1 packages remain valid.
- The second click triggers the browser download immediately from already prepared private bytes, after synchronously rechecking the opaque marker and raw localStorage drafts and markers. A changed source invalidates the prepared file and requires a fresh prepare step; a download request is not proof a file was actually saved. No automatic replay, server upload, telemetry, local public cache or URL parameters.
- Sign-out reports an error if its local purge fails, even if the server session already ended; it must not claim successful local removal. Normal Node tests without a browser must not interpret missing `window` / `localStorage` globals as a recovery hold; actual browsers still fail closed on storage errors.
- Cleanup of pending send markers, note drafts and project-context drafts is forbidden during the hold even if initiated by an earlier save. The Dexie guard rejects even an adoption-authorized mutation when another tab has installed the hold; a failed adoption must not fall back to wiping the database. IndexedDB snapshots are read after prior write transactions have settled.

## Explicitly not finished

1. **No release/continue button yet.** The persistent hold can only be resolved by a future audited workflow that verifies a recovery file and obtains explicit owner consent to adopt or reconcile. Do not manually delete the hold or clear browser site data before independently preserving all owner work. Because of this limitation, this implementation remains a **draft, not suitable for merging/deployment** as a completed restore workflow.
2. In-flight local transactions from before the hold must be subjected to browser-focused concurrency/crash testing beyond the current IndexedDB read barrier and double-read check. Multi-tab race, tab closure, reload, missing localStorage, expired sign-in, malformed drafts and >12 MiB data must be covered in a dedicated integration/release test. A concurrent tab or browser failure can still invalidate the source; an export is a safety copy, not proof that the source was never modified before the hold.
3. A local file is sensitive, unencrypted JSON. Users must keep it secure. Server-side membership/Area ACL verification remains required before any future recovery.
4. Server 2b migration, workspace partition, `restoreGeneration` bump, 2c assignment backfill and D3 view enablement remain blocked.

## Validation

The targeted node tests in `tests/d2b-pre-adoption-recovery.test.mjs` exercise persistency, raw legacy storage, malformed entries and fail-closed rejection. PR Checks must independently pass on the final HEAD: deployment shell syntax, typecheck, complete unit suite and production build. Dedicated focused Playwright restore scenarios are required before merge. The **full browser E2E suite remains a pre-deployment release gate for exact main SHA only**, per AGENTS.md.
