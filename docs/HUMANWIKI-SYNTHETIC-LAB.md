# HumanWiki H0 / H1-synthetic laboratory

This is an offline design probe for [LUMI-FR-014](PRODUCT.md#lumi-fr-014) and the [HumanWiki decision](decisions/2026-11-08-humanwiki-knowledge-bootstrap.md). It is isolated in `scripts/humanwiki-synthetic`; no application route, Context Graph writer, database migration, provider call, account connector, or upload endpoint invokes it. The CLI accepts only the two checked-in fictional fixtures. It has no path argument for a real export. Its marker `synthetic_fixture: true` is a fixture convention, **not** an authorization control for production data.

Run `node scripts/humanwiki-synthetic/run.mjs chatgpt 1`, then run it again to resume the next message. Omit the final number to finish the bundled fixture. Use `claude` for the other fixture. The private local checkpoint lives in the OS temporary directory under `lumi-humanwiki-synthetic-lab`; delete that directory to restart the lab. It contains only the bundled fictional text and is never a production store. The CLI prints non-content counts and source ID. `node --test tests/humanwiki-synthetic.test.mjs` runs the focused contract tests.

The two allowlisted shapes mimic a narrow text-only ChatGPT `mapping` and Claude `chat_messages` structure; they do not assert compatibility with actual provider export versions. Parser limits: 256 KiB bundle, 50 conversations, 1,000 messages and 8,192 characters per message. Unsupported content, missing stable IDs, duplicate IDs, bad time, or unknown bundle shape fail with a clear error. Messages are sorted by stable IDs so replay order is deterministic. Each nonempty line gets an exact source/conversation/message/line locator, speaker, observation time, content digest, and conservative provenance. Markdown `>` lines are tagged `quoted_third_party` with `speaker=unknown` and a separate enclosing message speaker, so a quote never inherits the owner's identity. Text from assistant turns remains `assistant_generated`; other roles remain `unknown`. This is only a simple quote heuristic: inline quotations, code fences, attachments, branch semantics, edited/deleted messages, and provider-specific metadata need later adapters and tests. The fixture text is untrusted data and is never executed as instructions.

The staged record has `review=proposed`, `freshness=current`, an independent `disputed=false` axis, `sensitivity=unclassified`, and `scope=owner_private_unassigned`. It is a source segment, **not a claim**: no automatic identity resolution, fact extraction, confirmation, sharing, task, or external action occurs. In particular an assistant's fictional ownership assertion remains assistant-authored evidence, not proof of owner biography. Quoted text does not inherit the enclosing user speaker's provenance. Unknown sensitivity bars any future egress or sharing until classification and consent are implemented.

The checkpoint binds source ID and bundle digest to the next-message cursor. Resume replays and validates every prior record before advancing, so a truncated/edited checkpoint or changed fixture fails closed instead of skipping input. The CLI requires its checkpoint directory to be owned by the current user, private, and not a symlink. It writes the entire state to a private temporary file, syncs it, atomically renames it and syncs the directory. An older lab checkpoint schema is deliberately rejected; delete only this lab's temporary directory to restart. This proves local replay and idempotence for the fixture; it does **not** implement the production consent ledger, encrypted quarantine, independent revocation witness, ACL, cross-source evidence independence, Context Resolver, or safe real-export retention. H1-real remains blocked by the R2d/R3 identity, ACL, sync, resolver and revocation gate, explicit consent, and the R4 production gate. Gmail content remains outside this lab and subject to its existing no-body/no-excerpt/no-background rule.
